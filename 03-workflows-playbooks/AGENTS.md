# FAST GITHUB OUTPUT WORKFLOW

Wenn der Nutzer eine Website-Demo, Modernisierung oder lokale Business-Seite will, die am Ende bei GitHub Pages sichtbar sein soll:

- Nutze den Fast Path aus `FAST_GITHUB_WEBSITE_WORKFLOW.md`.
- Arbeite direkt von Prompt -> Analyse -> Demo in `demos/<slug>` -> Preview -> GitHub-Pages-Repo in `github-work/<repo>` -> Publish.
- Nutze bevorzugt `tools\Build-Verify-Publish.ps1`, statt Cache-Buster, Screenshots, Publish und Pages-Check einzeln manuell zu wiederholen.
- Frage nur nach, wenn URL, Zielbranche, Repo oder Publishing-Ziel nicht sinnvoll ableitbar sind.
- Final immer kurz liefern: Live-Link, geaenderte Dateien, Vorschau-Screenshots und naechste Conversion-Hebel.

Bei Vorher/Nachher-Reels gilt: Nur die beschriebene Leistung veraendern. Keine ungefragten Nebenverwandlungen bei Bart, Gesicht, Alter, Kleidung oder Identitaet. Ein Fade darf keinen ploetzlich volleren Bart erzeugen; ein Beard-Line-up soll nur Linien/Seiten/Pflegegrad verbessern, keine komplette Typveraenderung.
